The client's own app POSTs security events here (login failures, 403s, 404s, or a flagged critical error) -- nothing here scans or probes anything. Site sits behind Cloudflare? Skip the webhook

If the target is proxied through Cloudflare, a Logpush job can feed this directly from the edge -- no code change on the client's site. It only ever forwards two things: 404s (feeds the scanning rule) and 5xx origin/edge errors (feeds the critical-error rule). Regenerating the URL above also changes this one, since they share the same token.

In the Cloudflare dashboard: Logpush (zone level) → Create a Logpush job → dataset HTTP requests → destination HTTP, paste the URL above as the endpoint → under Send the following fields, select only: {{ cloudflare_fields|join(', ') }} → set the timestamp format to RFC3339 → Submit. Cloudflare validates the destination automatically (no ownership file needed) and starts delivering shortly after.
